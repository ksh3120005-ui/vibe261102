| 작성일 | 2026-11-02 |
| 상태 | 설계 단계 (구현 전) |

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 체크하고, 정리할 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구 대신 **"오늘"에만 집중**하는 단순한 도구를 목표로 한다.

### 1.2 목표
- 설치·회원가입 없이 브라우저에서 바로 사용할 수 있다.
- 3초 안에 할일 하나를 추가할 수 있다.
- 새로고침하거나 브라우저를 껐다 켜도 데이터가 유지된다.
- 데스크톱과 모바일 모두에서 편하게 쓸 수 있다.

### 1.3 비목표 (이번 범위에서 제외)
- 회원가입/로그인, 서버 동기화, 여러 기기 간 공유
- 협업(다른 사용자와 할일 공유)
- 반복 일정, 캘린더 연동, 푸시 알림
- 하위 할일(서브태스크), 첨부파일

## 4. 기능 요구사항

### 4.1 헤더 영역
- **FR-01** 오늘 날짜를 `2026년 11월 2일 (월)` 형식으로 표시한다.
- **FR-02** 진행률을 `3 / 5 완료` 텍스트와 프로그레스 바로 표시한다.
- **FR-03** 모든 할일을 완료하면 축하 메시지(예: "오늘 할일 완료! 🎉")를 표시한다.

### 4.2 할일 추가
- **FR-04** 상단 입력창에 텍스트 입력 후 Enter 또는 `추가` 버튼으로 추가한다.
- **FR-05** 공백만 있는 입력은 추가하지 않는다. 앞뒤 공백은 제거한다.
- **FR-06** 최대 길이는 100자로 제한하고, 초과 시 입력을 막는다.
- **FR-07** 추가 시 우선순위를 선택할 수 있다 (기본값: 보통).
- **FR-08** 추가 후 입력창은 비워지고 포커스가 유지된다.

### 4.3 할일 목록
- **FR-09** 각 항목은 `체크박스 · 우선순위 표시 · 내용 · 수정 · 삭제`로 구성된다.
- **FR-10** 완료된 항목은 취소선과 흐린 색으로 표시하고 목록 하단으로 이동한다.
- **FR-11** 기본 정렬: 미완료(우선순위 높은 순 → 생성 순) → 완료(완료 순).
- **FR-12** 목록이 비어 있으면 빈 상태 안내("오늘 할 일을 추가해보세요")를 표시한다.

### 4.4 수정 / 삭제
- **FR-13** 내용을 더블클릭하거나 수정 버튼을 누르면 인라인 편집 모드가 된다.
- **FR-14** 편집 중 Enter는 저장, Esc는 취소. 빈 값으로 저장하면 취소로 처리한다.
- **FR-15** 삭제 버튼 클릭 시 즉시 삭제하고, 5초간 "실행 취소" 토스트를 띄운다.
- **FR-16** `완료 항목 지우기` 버튼으로 완료된 항목을 일괄 삭제한다 (확인 대화상자 표시).

### 4.5 필터
- **FR-17** `전체 / 진행 중 / 완료` 탭으로 목록을 필터링한다. 각 탭에 개수를 표시한다.
- **FR-18** 선택한 필터는 새로고침 후에도 유지된다.

### 4.6 데이터 저장
- **FR-19** 모든 데이터는 브라우저 `localStorage`에 저장한다.
- **FR-20** 변경(추가/수정/삭제/체크)이 일어날 때마다 즉시 저장한다.
- **FR-21** 저장 데이터가 손상되었거나 읽을 수 없으면 빈 목록으로 시작하고 앱이 멈추지 않는다.

### 4.7 날짜 처리 (P2)
- **FR-22** 할일은 생성 날짜를 가진다. 페이지는 오늘 날짜의 할일만 보여준다.
- **FR-23** 이전 날짜의 미완료 할일이 있으면 "어제 못 끝낸 할일 N개 가져오기" 배너를 표시한다.

## 7. 데이터 모델

### 7.1 Todo 객체
```ts
interface Todo {
  id: string;              // crypto.randomUUID()
  text: string;            // 1~100자
  completed: boolean;
  priority: 'high' | 'medium' | 'low';
  date: string;            // 'YYYY-MM-DD' (로컬 기준, 할일이 속한 날짜)
  createdAt: number;       // epoch ms
  completedAt: number | null;
  order: number;           // 수동 정렬용 (P2)
}
```

### 7.2 localStorage 키
| 키 | 값 | 설명 |
|---|---|---|
| `todolist.v1.todos` | `Todo[]` (JSON) | 전체 할일 |
| `todolist.v1.filter` | `'all' \| 'active' \| 'done'` | 마지막 선택 필터 |
| `todolist.v1.theme` | `'light' \| 'dark' \| 'system'` | 테마 (P2) |

> 키에 버전(`v1`)을 붙여 추후 스키마 변경 시 마이그레이션할 수 있게 한다.

## 8. 기술 설계

### 8.1 기술 스택
- **HTML + CSS + Vanilla JavaScript** — 빌드 도구 없이 정적 파일로 동작
  - ES Modules는 `file://`에서 CORS로 막히므로, `index.html`을 바로 열 수 있도록 일반 `<script>` + 전역 네임스페이스(`window.TodoApp`) 방식으로 모듈을 나눈다.
- 외부 라이브러리 없음 (드래그 정렬은 HTML5 Drag and Drop API 사용)
- 배포: 정적 호스팅 (GitHub Pages / Netlify 등) 또는 로컬에서 `index.html` 열기

> 선정 이유: 기능 규모가 작아 프레임워크가 불필요하고, 의존성 없이 유지보수가 쉽다. 규모가 커지면 React/Vite로 이전을 검토한다.

### 8.2 폴더 구조 (예정)
```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업
├── css/
│   └── style.css     # 스타일, 반응형, 다크 모드
└── js/
    ├── app.js        # 진입점, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 입출력
    ├── render.js     # DOM 렌더링
    └── utils.js      # 날짜 포맷, id 생성 등
```

### 8.3 아키텍처 (단방향 데이터 흐름)
```
사용자 이벤트 → app.js (핸들러)
             → store.js (상태 변경 + 저장)
             → render.js (상태 기반 화면 다시 그리기)
```
- 상태는 `store` 한 곳에서만 변경한다.
- `store.subscribe(render)` 형태로 상태가 바뀌면 화면을 다시 그린다.

### 8.4 store 주요 함수
| 함수 | 설명 |
|---|---|
| `load()` | localStorage에서 읽기, 실패 시 빈 배열 |
| `save()` | 현재 상태를 localStorage에 쓰기 |
| `addTodo(text, priority)` | 할일 추가 |
| `toggleTodo(id)` | 완료 상태 토글, `completedAt` 갱신 |
| `updateTodo(id, patch)` | 내용/우선순위 수정 |
| `deleteTodo(id)` | 삭제 (실행 취소용으로 직전 항목 보관) |
| `undoDelete()` | 마지막 삭제 복구 |
| `clearCompleted()` | 완료 항목 일괄 삭제 |
| `setFilter(filter)` | 필터 변경 |
| `getVisibleTodos()` | 오늘 날짜 + 필터 + 정렬 적용 결과 |
| `getStats()` | `{ total, active, done }` |

## 9. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 공백만 입력 | 추가하지 않음, 입력창 흔들림 등 가벼운 피드백 |
| 100자 초과 | `maxlength`로 입력 차단 |
| HTML 태그 입력 (`<script>`) | 텍스트 그대로 표시 (`textContent` 사용) |
| localStorage 비활성화(사생활 보호 모드) | 메모리에서만 동작 + "저장되지 않습니다" 안내 |
| localStorage 데이터 손상 | try/catch로 무시하고 빈 목록 시작 |
| 자정이 지나 페이지를 계속 열어둔 경우 | 포커스 복귀 시 날짜 재확인 후 갱신 |
| 여러 탭에서 동시에 사용 | `storage` 이벤트로 다른 탭 변경 반영 |

## 11. 성공 지표 (수용 기준)
- 할일 추가 → 새로고침 → 동일 목록이 그대로 보인다.
- 마우스 없이 Tab/Enter/Space/Esc 만으로 추가·완료·수정·삭제가 가능하다.
- 360px 폭 모바일 화면에서 가로 스크롤이 생기지 않는다.
- `<img src=x onerror=alert(1)>` 입력 시 스크립트가 실행되지 않는다.
